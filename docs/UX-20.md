> 本轮目标：在「单文件、极简、高性能」的前提下，把已知限制补齐，
> 并把阅读体验从「能用」推到「顺手」。凡涉及千万字预览的改动，都必须

## 本轮修复记录（实测发现）

1. **滚动偏移超出内容总高 → 整屏空白**：`MJ_SCROLL=99999999` 时首帧视口落在内容之外，
   `find()` 钳制后画的是末块但位置在视口外，且 egui 闲置不再重绘。修复：初始偏移
   （CLI 恢复 / 目录跳转 / 阅读位置恢复）统一钳到 `total - 400`（`vpreview.rs`）。
2. **Mermaid 有回边时下游全塌到第 0 层**：Kahn 分层遇到 `D→B` 回边，B 的入度永远清不了零，
   B/C/D/E 全卡第 0 层。修复：`assign_layers` 改为「Kahn + 环上打豁口」，回边只画箭头不参与定层，
   加回归测试 `back_edge_does_not_collapse_layers`（31 个单测全过）。
3. **数学公式豆腐块**：雅黑只有 2/20 的上下标字形（₀₁₃、₌、ᵢ 缺失）。实测 Segoe UI 20/20 全覆盖，
   加入字体 fallback 链（正文/粗体字族）。
4. **命令行打开文件不生效**：main.rs 从未读 argv，交接文档里的 `mojuan.exe huge.md` 测试命令前提不成立。
   补上 argv 支持（忽略 `-` 开头选项），这也是文件关联双击的前提。

## 明确不做（保持极简）

- 不引入 WebView2 / Chromium / JS 引擎：数学与 Mermaid 都是 Rust 自绘。
- 不引入网络库：更新与远程图片复用系统 WinHTTP。
- 不做整篇虚拟 DOM：egui 是立即模式，虚拟滚动靠「索引 + 高度树 + 视口裁剪」，
  比维护一棵常驻渲染树更轻。
- 大文档编辑窗口内的撤销栈只覆盖当前窗口；跨窗口撤销需要额外的编辑历史结构，
  目前不值得为此增加内存与复杂度。

## 性能验收口径

- 文档：`huge.md`，约 **1050 万字符 / 22 MB**，含数万块。
- 冷启动：从进程启动到首帧可读，包含建索引 + 目录 + 统计。
- 滚动：只解析可见块，帧内解析量与窗口高度成正比。
- 跳转：目录任意位置 O(log n) 定位，不扫描全文。
- 内存：只保存一份原文 + 偏移表 + 高度数组 + 320 块解析缓存，不保存整篇 AST。
